HarfBuzz-only 迁移：24 个主任务与 2 个字体下载子任务 ​

已确定的决策 ​

基于 fd11752e 的代码评估，配套架构说明见 移除方案。 各任务状态以实现记录为准，未标记完成的项目仍待实施。 2026-10-22：T01–T24 的实现与验收已完成，当前 Node24/浏览器、发行、资源与删除审计 见 T23/T24 最终验收。性能有明确成本与适用边界， 不宣称增量开关一定更快；DEFER-010 的性能优化与 SVG 实现继续保留。 协议说明见 T03 布局协议，基线见 迁移记录。

  1. 缺字允许继续编辑：所有已加载字体都不能覆盖某些文字时，按下载开关选择自动补字体 或页面/控制台提示；保留原文和占位，补字体后复核。
  2. Bunny Fonts 自动补字体本期实现：新增 autoDownloadFonts，默认 true。 开启后按文字类别从 Bunny Fonts 下载基本字体；关闭时只提示手动补充字体包。 DEFER-026 已作为本轮必做项完成实现和下载验收，2026-10-22 关闭。
  3. 有效布局逻辑拆出保留：先拆出旧循环里的表格、对象、段落和流布局职责， 然后替换调用并删除旧调度与文字算法，不用删功能的方式完成迁移。
  4. 只发布 ESM：取消 UMD，不做 UMD/WASM 兼容封装，不提供 CommonJS 发行入口。
  5. 严格单一文字排版源：所有正常文字均由 HarfBuzz 整形并提供布局度量； 缺字占位是显式异常对象，不会进入浏览器文字整形或旧引擎。

正常 DOM 工具栏、输入代理、表格边框、图片与数学公式自身的渲染不属于旧文字引擎。 bidi-js、逻辑/视觉光标语义也继续保留。

执行规则 ​

  • 推荐按 T01 → T24 顺序执行，每项形成一个可审查提交；任务较大时内部再按职责拆提交。
  • T06 后插入 T06A、T06B，再执行 T07；既有任务编号保持稳定，共 26 项可执行工作。
  • 每个提交只处理本项及其必需测试，不能用“后面会补”掩盖功能丢失。
  • 中间步骤允许旧路径作为迁移对照；T20 之后生产包不允许再有旧引擎。
  • 新布局先实现为独立入口；现有消费方需要时可在宿主边界临时转换， T17 接入原生几何、T19 删除该转换，禁止把旧文字算法混入新引擎。
  • 所有新模块名与新增 API 均为设计目标，不是对现有代码的描述。
  • 一项完成后记录提交、执行命令、验收结果和遗留问题，再进入依赖它的任务。
  • 字体缺字是可恢复状态；WASM 或必要基础资源初始化失败才进入失败状态。

一、缺字处理的固定契约 ​

检测规则 ​

按以下顺序选择字体：显式字体与字重/样式 → 文种首选字体 → 其他已加载且允许用于备用的字体。 只要存在可正确整形的候选字体，就使用它；不能因为首选字体缺字而误报“所有字体缺失”。

覆盖检查必须同时参考字体字符映射和 HB 实际整形结果：

  • 使用 Unicode 标量值，不能将代理对拆成两个缺字。
  • 以 grapheme/cluster 及整形上下文检查组合符、emoji/ZWJ 和 variation selector。
  • 不能把空格、换行、BiDi 隔离符、默认不可见字符“无轮廓”误判为缺字。
  • “缺字体文件”“文件加载/解析失败”“缺字符/序列”“不支持字形绘制格式”分开报告。
  • Script 只表示文字类别，不能由 Han 字符推断内容一定是中文或某一种语言。 当前 scriptFont.ts 的区间正则需要覆盖补充平面和未知类别，不能作为完整覆盖检查。

诊断数据与接口 ​

建议新增以下语义结构，字段名可在 T03/T06 中最终定型，但不能丢失其含义：

信息用途
documentRevision、fontRevision防止旧扫描结果覆盖新文档或新字体的状态
reason缺字、缺序列、字体加载失败、字形格式不支持等可区分原因
script、categoryLabel稳定文种标识与“汉字/CJK、阿拉伯字母、emoji、未知文字”等提示
missingCharacters、missingSequences去重后的字符与完整序列，供后续字体查询或子集请求使用
codePointsUnicode 标量码点列表，例如 U+20000，不保存成代理对码点
uniqueCount、occurrenceCount不重复的缺字数量与出现次数分别统计
samples有上限的示例，页面/日志默认最多展示 16 个 grapheme

新增 fontCoverageChange 事件与 getFontCoverageReport 查询入口。 事件携带可比较的当前快照，不仅是一次性的控制台字符串；宿主晚订阅时也能查询状态。 补字体使用明确的公共注册入口，例如 editor.register.fonts(faces): Promise<FontRegistrationResult[]>。

下载开关与固定行为 ​

以下是待实施的配置设计，不是当前已存在的 API：

typescript
const editor = new Editor(container, data, {
  autoDownloadFonts: true // 默认值；false 时仅提示手动补充字体包
})
场景页面行为控制台与网络行为
开关未配置或 true，现有字体已覆盖正常显示不发送额外字体请求
true，首次发现缺字显示“正在补充某类文字的基础字体”，占位可编辑合并缺字请求，从 Bunny Fonts 取字体；可恢复加载中状态不重复 warn
true，下载成功且重新检测通过原文重新排版，撤销加载/缺字提示更新 fontRevision；相同已缓存字体不重复下载
true，下载失败/无适用字体/仍有缺字显示类别、样例、原因，提示手动补充字体包去重 warn；本轮不无限尝试其他服务商或重复请求
false，发现缺字立即提示手动补充字体包去重 warn；禁止自动 Bunny CSS/字体请求和预连接

false 不禁止宿主显式配置的 fonts.url 或手动字体注册。 切换为 false 后停止排队请求、取消本实例请求订阅，不移除已注册字体； 共享请求仍被其他实例需要时继续，最后一个订阅取消时才中止。 切换回 true 后只处理当前仍缺失的文字。缓存命中可直接注册，不需要新的网络请求。

页面、控制台和占位行为 ​

  • 页面默认提供编辑器实例内的非阻塞状态区域，例如： “缺少可显示汉字/CJK 的字体：8 个不同字符。示例：𠀀、汉。请补充覆盖这些字符的字体。”
  • 状态区域支持展开查看分类和码点，使用现有 i18n 和 UI 方向规则，具有可访问的状态语义。
  • 状态区域不改变画布坐标原点，不进入文档模型、历史、分页、图片导出或打印。
  • 自动下载关闭、下载失败或下载后仍缺字时，控制台按新增/变化的缺失集合去重 console.warn； 重复重绘或重复输入同一缺字不刷屏。 完整字符列表保留在诊断接口，日志不打印整篇内容或完整来源片段。
  • 不重复弹 alert；多个编辑器各自维护提示，destroy 时清理 DOM 和订阅。
  • 文档删除相关文字、替换内容、补字体、字体加载失败或设计态变化后重新计算当前快照。
  • 有缺字时 ready 正常完成，保存/复制保留原文；占位有稳定几何与索引，仍可定位和删除。
  • 优先使用基础字体的 .notdef 字形及其度量；不可绘制时使用明确的 MissingGlyphBox。 此盒不冒充真实字宽，不调用 measureText/fillText，也不替换持久化文字。
  • 下载与排版异步完成，不能覆盖过期文档 revision，不能在 destroy 后更新页面或重新挂载。

Bunny Fonts 字体选择与传输协议 ​

使用 Bunny Fonts 的字体目录与 CSS 接口 https://fonts.bunny.net/css。 “对应语言”在实现中拆成 Script/实际码点覆盖与必要的地区字形提示，不能只按 UI 语言选字体。 优先使用用户已配置的字体；自动下载的基本字体只补未覆盖内容，不覆盖全文 font 样式。

首版候选映射如下，真正覆盖能力以下载字体的 cmap 与 HB 整形复核为准：

文字类别首选基本字体候选
Latin/Greek/CyrillicNoto Sans
汉字/CJK，缺少语言提示Noto Sans SC；如文档明确繁体或日文，选择相应地区字体
繁体中文字形Noto Sans TC
日文Noto Sans JP
阿拉伯文字Noto Naskh Arabic
天城文Noto Sans Devanagari
泰文Noto Sans Thai
其他类别、emoji、未知序列从经过验证的映射表选择；没有适用条目时提示手动补字体包

基本字体默认使用 400 normal。目标样式存在已验证可用的字重/斜体时按需追加， 不能把样式缺失误报成字符缺失，也不能宣称 regular 等同于真实 bold/italic。 基础字形或样式均无法满足时按诊断类型提示，不回退浏览器整形。

下载管线必须完成：

  1. 以字体家族、文种/地区、字重/样式查询 CSS 元数据；不猜测未验证的字体文件地址。
  2. 解析 @font-face 的 URL、格式、样式和 unicode-range；按本地所需 cluster 与上下文 选择字体片段，不能只下载 CJK 的 Latin 片段，也不能默认拉取全部大型字体片段。
  3. 下载字体二进制 ArrayBuffer，归一化成 HB 与字形后端可读取的数据，然后注册。 插入 <link> 或 CSS @import 本身不满足 HarfBuzz 字体注册需求。
  4. T06A 必须验证 TTF/OTF/WOFF/WOFF2 格式；当前安装的 opentype.js 遇到 WOFF2 会要求外部解压器，因此要接入经过测试的解压/格式适配，不能等下载成功后再失败。
  5. FontManager 的缓存标识要包含字体片段或内容标识，不能仅按 family/weight/style 去重，否则同一 CJK 家族的不同 unicode-range 片段会覆盖或被忽略。
  6. 合并相同请求，限制并发，设置超时和有限重试；失败有负缓存和手动重试入口。
  7. 内存及持久缓存按提供方、家族、样式、片段和资源版本隔离，带淘汰与再验证策略； Bunny 字体会更新，不能只用 family 名称永久复用旧资源。
  8. 字体注册后重新检查实际缺字范围，更新字体版本并使相关布局 scope 失效。 下载成功不等于全部缺字已解决，不启动无限下载循环。

按基本字体/片段下载，不依赖服务端按文字子集生成能力；文档原文和缺字样例不拼进请求 URL。 T06A/T06B 验收时实测 CSS/字体跨域读取、重定向、Content-Type、字体格式和资源更新行为。 本轮方案调研确认目录/API 描述，未把端到端二进制下载与解码标记为已验证。

来源核对：Bunny 官方 API 说明、 字体更新说明、Noto Sans SC、 Noto Sans、 Noto Naskh Arabic、 Noto Sans Devanagari、 Noto Sans Thai、 Noto Sans TC、 Noto Sans JP。 接口是字体 CSS API，不假设存在“输入语言即自动返回正确基本字体”的接口。

  • 落点：新 BunnyFontProvider/字体映射表、字体二进制解码器、FontManager。

三、依赖与阶段门槛 ​

阶段门槛必须具备的能力
G1：允许接入新文字路径只发 ESM；Runtime/ready 可观察；默认自动从 Bunny 补基本字体，关闭/失败有双通道提示
G2：允许切换完整文档入口全脚本 HB 与字形绘制可用；表格/控件/对象/文档流职责已迁出旧循环
G3：允许物理删除旧实现Position/命中/光标/装饰/测量/增量/历史均不依赖旧行模型和旧粒子
G4：允许宣称彻底完成真实浏览器和发布验收通过；没有隐式旧路径；Bunny 自动下载开关与失败闭环已验收

四、每项交付的最小检查 ​

  • 有语义代码变更时运行 ESLint、TypeScript 与相关单测。
  • 影响共用布局/模型/交互时运行全量单测与相关 Cypress；按样本比较实际绘制。
  • ESM、Runtime 或资源路径变更时运行库/应用构建和独立消费端测试。
  • 删除项须同时提交引用审计，不能仅依赖“编译没报错”。
  • 记录字体、视口、DPR 和样本文档；缺字测试必须刻意使用不覆盖目标文字的字体。
  • 文档计划修改本身不需要重复运行代码测试；不能将规划写入当成实现验收通过。

本执行清单不承诺固定工期。每项完成后再记录实际耗时与剩余风险， 避免在字体后端、对象布局尚未验证前给出没有依据的总时长。
