Benchmark: typing and sustained deletion ​

Updated November 3, 2026. See the latest three-engine IME rerun and performance principles for mechanisms and tradeoffs. The ordinary typing/deletion figures below are historical October 23 measurements; later dated IME studies have separate workloads and must not be pooled with them. All optimized results use explicit experimental configuration; the default remains baseline. See configuration and fallback.

Method ​

Apple M1 Pro, 8 logical CPUs, 16 GiB, Darwin 25.4.0, Node 24.19.0. Fixed NotoNaskhArabic-Regular.ttf SHA256: 67b5a525a661b607971fbd3f96a81b89d3a768e74534fca84f18ac97e6fab72f.

Chrome changed from 155.0.8059.85 in historical runs to 155.0.8059.86 in the final runs. These are same-machine historical trends, not a strict same-browser A/B; timing differences cannot be attributed entirely to code changes.

Standard cases use middle edits, paging, history on, paragraph cache off, DPR 1, one warmup and 2Hz for 10 seconds (20 operations per configuration). The initial baseline has one trial; preceding and final results have three. Tables compare fixed trial 0, rather than selecting the fastest trial. Units are milliseconds. Input uses the input handler; deletion uses the keydown handler.

Geometry commit is an event-to-geometry proxy. Offer-to-geometry also includes driver queueing. Neither measures screen presentation. Inclusive stages overlap and must not be added together.

Validation and release status ​

The full Vitest run passed 169 files/1072 tests; after final geometry, destruction and idle-boundary fixes, four targeted files/50 tests passed again. TypeScript, ESLint and the final library build passed. Final Chrome differential checks covered six groups/four modes, 348 structural comparisons and exact exported RGBA equality, including Unicode, RTL, tables, history and crash/budget recovery, with no page errors. Final benchmark data covers 50 cases/5280 operations.

Six create/edit/destroy cycles cleared workers, canvases, observers, pending requests and path caches. Forced-GC JS heap ranged from 14223020 to 14232228 bytes (about 13.56–13.57MiB). This supports short-term JS cleanup only, not long-term native/WASM/GPU memory stability.

Release status remains hold against fixed handler P95 ≤8ms and geometry P95 ≤32ms budgets. Keep baseline as default, sync opt-in, Worker experimental and transfer deferred. OS IME/key repeat, actual presentation, long-term memory and fresh Firefox/WebKit checks remain required. Historical browser results do not validate the latest fixes. Follow testing and acceptance to regenerate evidence.

2026-10-30: experimental IME preview ​

The same-revision comparison covers five documents, baseline/sync profiles, preview off/on and three trials: 60 cases/420 preedit updates, plus a separate uninstrumented control with 12 cases/84 updates. Environment: M1 Pro, 16 GiB, Darwin 25.4.0, Node 24.22.1, Chrome 156.0.8078.76, fixed Latin/CJK fonts, DPR 1. These are synthetic, untrusted events. The browser requests a 33ms timer interval; blocking increases actual spacing, so this is not a fixed-rate external input test. Only seven updates per trial means P95 equals the maximum in each trial.

For 1000 short paragraphs under baseline, handler P95 ranges changed from 206.1–308.7ms to 0.1–0.2ms, and geometry-completion proxy P95 from 206.0–308.7ms to 12.8–18.0ms. Under sync, the geometry proxy changed from 19.6–21.3ms to 9.4–9.8ms. Preedit whole-document geometry calls fell from seven to zero per trial in supported simple single-line paragraphs.

Short cases incur frame waiting: sync geometry proxy rose from 2.9–3.5ms to 12.8–17.8ms. Long paragraphs and tables retain the synchronous fallback, with seven full computations per trial; these paths retain layout costs and can add frame waiting. A small handler alone does not prove smoother presentation. Final commits and history restoration retain layout costs. Geometry and next-rAF timings are proxies, not actual pixel presentation. Whole-session frame gaps also contain final commit/history work; filter raw frames by composition boundaries for preedit analysis.

All 12 pixel comparisons matched the synchronous reference, including glyphs and composition underlines. Full quality/build checks passed 172 files/1089 tests; final boundary checks passed another six targeted files/28 tests, followed by 15 tests after the consecutive-session fix. Real OS IME, candidate-window placement and presentation remain pending. imePreview stays opt-in and is not enabled by profiles. Historical October 23 hashes remain unchanged.

See the complete Chinese results, three-trial evidence, uninstrumented control, and IME tasks and reproduction.

Filtering rAF callbacks to composition boundaries, thousand-paragraph frame-gap P95 ranges changed from 205.4–229.3ms to 17.3–17.5ms under baseline and from 25.0–29.7ms to 16.9–17.5ms under sync. These are callback-cadence observations, not actual display FPS or OS IME measurements.

Zoom commands retain the active session. Chrome checks cover DPR 1/2, local preview, pagination, RTL and tables, including nested scrolling, editor zoom and CSS transforms. These are DOM geometry checks, not OS candidate-window or FPS measurements. Real IME recordings remain pending. See the IME-08 implementation and manual procedure.

IME-09 composition closure ​

November 2, 2026: final synchronous callbacks now follow history commit and old session cleanup. Cancellation restores complex content, selection and typing style without altering prior history. Safe text replacement history retains only original and final fragments, while mirrors still receive every committed revision. Async export includes graffiti and owns its request-time snapshot. The semantic browser matrix covers baseline/sync/worker, five document shapes, worker-denied fallback and a delayed real Worker layout response. Tables retain synchronous layout. These are synthetic correctness checks, not new latency/FPS measurements or real OS IME acceptance. Historical timing evidence is unchanged. See IME-09.

IME-10 range flow commits ​

November 2, 2026: same-code comparison switches only incrementalCommit, retaining all earlier sync-profile optimizations. Three trials × 20 samples give 60 samples per mode/scenario. Thousand-paragraph synchronous final-commit P95 changed from 17.2→14.7ms without wrapping, 225.0→42.2ms with added wrapping, and 272.5→144.4ms with added pages. Nonwrapping max did not improve (22.9→23.2ms).

Cached-break re-placement removes 499 repeated paragraph callbacks in the two reflow cases. Their position stage gets slower (P95 15.8→27.5ms and 16.5→36.3ms), even though total commit time drops substantially. Existing geometry/run/query reuse is not credited as new work. Directory, page assembly and full position snapshot costs remain global. These are core compositionend timings, excluding DOM dispatch and later paint/notifications; they are not actual presentation or OS IME FPS. All slow samples of the final three-trial implementation are retained as summaries/traces. Historical timing evidence remains unchanged.

IME-11 long-paragraph preview windows ​

November 2, 2026: same-code imeWindowPreview comparison, three alternating trials, 105 updates per mode/scenario. P95 was 83.2→2.1ms for the final row of a 3506-element CJK/Latin paragraph, 223.8→6.4ms for an 8056-element Latin paragraph, and 84.5→76.2ms for a middle-row replacement. The middle case retains 45/105 full-layout fallbacks; its P95 benefit is only 9.8%. Max values are respectively 98.9→3.9ms, 309.6→17.8ms and 102.9→89.5ms.

The successful final-row windows layout two rows, skipping 57/115 other rows. Separate profiling records scanning, shaping/cache projection, breaking, native measurement and geometry-item counts. Warm CJK runs already have no HarfBuzz misses in either mode; the benefit is less scanning, cache projection and geometry creation. Object counters cover named allocation sites, not total heap bytes. Window creation can still scan the full paragraph. Final commits remain formal layout, and changes to wrapping still fall back.

These are synchronous input + explicit preedit-flush timings from a Vite development fixture, including synchronous paint but excluding scheduled later paint, DOM dispatch and presentation. Chrome headless software rendering is fixed for 35 exact pixel/caret comparisons, including combining marks, ZWJ emoji missing boxes and actual-font Arabic fallback. Minor placeholder antialiasing differences were observed with the default GPU backend; GPU, real OS IME and cross-browser acceptance remain pending. These results are not measured IME FPS.

See methodology, stage costs and limitations and retained baseline/optimized summaries and hashes.

IME-12/13 tables and Worker composition ​

November 2, 2026: same-code comparisons, three alternating trials, 720 measured updates in a fixed-font Vite development fixture with Chrome headless software rendering. Table modes switch only imeTableLayout; body modes both use the worker preset and switch only imeWorkerPreview.

For a stable 24×4 table, child-layout callbacks drop 96→1 and grid rows solved 24→0. Geometry P95 is 6.8→4.7ms. With merged-cell growth/shrink, callbacks drop 94→1 while an average 16 rows still require solving; geometry P95 is 10.2→8.9ms. Aggregate tails improve, but two stable-table trials get slightly slower P95, and growth max is 10.3→10.6ms. Signature checks, positions and page assembly can remain global. These counters are not HarfBuzz calls or heap bytes.

Worker preview lowers handler P95, short line 1.3→0.6ms and wide-line stress 9.1→1.7ms, but geometry P95 worsens 1.5→4.1ms and 9.1→13.9ms. Wide-line next-rAF P95 worsens 17.2→23.0ms. Both modes have zero observed long tasks in the measured intervals, so no long-task reduction is demonstrated. Post-cancel synchronization P95 is ≤0.1ms after already waiting for each preview; this does not describe a hung Worker's drain time. Keep imeWorkerPreview disabled by default.

59 pixel/geometry/caret comparisons, five Worker recovery boundaries and two input bursts pass, including merged/nested/paged/repeated-header/RTL tables. The wide rapid-input burst reaches the deadline and safely switches to sync. Existing extreme nested overflow/caret limits remain; real OS IME candidate windows, GPU presentation and cross-browser release acceptance are pending. These are synthetic core/next-rAF measurements, not presented FPS.

See full distributions, work counts and the enablement decision, retained evidence and hashes, and implementation/reproduction.

IME-14 acceptance gate and cache capacity ​

November 3, 2026: over-capacity scans now protect hot cells from the current and previous layout pass. Failed admissions leave them intact; idle old documents can be reclaimed. A real 600-cell fixture reuses 512 cells and computes 88, while reusing 150 grid rows. Input checks still touch 2400 elements; this is not O(1).

The unified acceptance command serializes quality/build/package checks, Chrome/Firefox/WebKit correctness and three-trial timing. Pixel checks compare decoded RGBA rather than PNG encoding; cancellation checks drain older history notifications. Unsupported long-task APIs remain unavailable, never zero. Source fingerprints, required phases and handler/geometry budgets are checked separately from native OS IME evidence. Missing/unmet requirements keep hold and do not enable experimental features.

The user confirmed no native records are available. Real macOS/Windows candidate windows, visible refresh and mobile acceptance therefore remain pending. See the final aggregate and release decision and evidence/reproduction instructions.
