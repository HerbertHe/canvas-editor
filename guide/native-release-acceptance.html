T23 / T24：性能、资源、发行与最终删除验收 ​

执行日期：2026-10-22。当前发布线为 @herberthe/canvas-editor@0.1.0， 基于 1dd25c22 加本次 QA 工具与验收文档；未发布 npm、未恢复 SVG 实现。

结论：T23 测量与资源/发行检查、T24 最终删除验收已完成。 功能与资源门槛通过；性能成本已量化并披露，DEFER-010 的后续性能优化保持 pending。

验收范围与环境 ​

  • Node 24.22.0，满足包声明 >=24.13.1；macOS、Chrome 155.0.8059.85。
  • 性能固定 1366×720、DPR=1、480×640 纸张、32px 页边距、16px 字号、缩放 1。
  • 字体固定仓库 Noto Naskh Arabic TTF，SHA-256： 67b5a525a661b607971fbd3f96a81b89d3a768e74534fca84f18ac97e6fab72f。
  • 每个样本、每种增量设置各 3 次独立浏览器 context：一次预热编辑、8 次交替 x/y 单字替换、5 次只绘制。六个 T01 样本，加多段、单超长段、密集控件、大表格、集中缺字， 共 11 类、每版本 66 次实例采样。表格用例编辑单元格文本，控件用例编辑控件值。
  • 缺字样本刻意使用不覆盖 CJK/emoji 的字体；自动下载关闭，自动 Bunny 请求必须为零。
  • T01 历史基线 fd11752e 通过 git archive 导出到临时目录，链接相同已安装依赖； 只在 QA Vite 配置加入实际路径白名单与独立缓存，生产源码未修改。 同一 fixture、浏览器、字体与采样协议复测，未重录 T01/T10 几何快照。
  • 性能阶段串行，不与其他浏览器套件或全量单测并发。资源生命周期另跑， 不把该轮受其他功能测试影响的耗时纳入性能表。

T23：性能结果与可比性 ​

T01 原记录没有墙钟性能数据。以下是同机历史提交复测，不是当时留存的性能金图。 两版完成的工作不同：旧版存在浏览器文字绘制、对象回退与按文本保留的段落缓存； 当前版显式检测覆盖、生成字形路径、原生 cluster/caret 和对象几何。 新行高度/分页也不同，例如 7,701 元素的多段样本为旧版 10 页、当前 19 页。 因此可比较迁移的实际成本，不能把比值当成视觉等价算法的吞吐量比。

下面为 24 次热编辑耗时中位数，单位 ms，包含同步布局和强制全部页面绘制； 不包含 GPU 呈现、系统打印对话框、远程字体网络时延，不等于懒绘制下的真实键盘帧率。 交替两种文本会让旧版文本键缓存重复命中；这是本轮明确的热缓存协议，不能外推到所有输入。

冷实例与只绘制 ​

startup 从 Draw 构造开始，到 ready 后强制完整同步绘制结束；字体下载、文档规范化与 浏览器模块加载在此计时区间外。module + startup 额外包含页面模块就绪的观测时间， 是本地开发服务器的分段总和，不能等同网络冷缓存或用户感知 LCP。 每个 context 是冷 JS/WASM 实例，操作系统及浏览器磁盘缓存没有清空。

已定位的主要成本：

  1. IncrementalParagraphComputer 的缓存键序列化、布局克隆和 source 重定位都有成本； 多段正文省下整形，但仍需重建宿主视图、分页和所有交互坐标。
  2. 单超长段仍是同一个脏段，无法复用段内未修改行；整段重算后再缓存/克隆，可能更慢。
  3. 分栏、图片、列表等复杂结构保守退回完整 HB 流，不能保证增量收益； 当前开关也会进入若干段落级缓存路径，因此有额外缓存处理成本。
  4. 原生 Position/InteractionGeometry 建立真实簇、caret、选区位置；旧坐标成本明显更低。
  5. 当前字形轮廓绘制、更多实际页面和覆盖诊断执行旧版未执行的工作。 未为追求旧版数字而恢复浏览器文字绘制或关闭布局特性。

集中缺字样本完整 HB 的覆盖扫描约 9.10ms/编辑，其中 resolve 约 6.12ms， 诊断更新约 0.75ms。三轮均只有启动时 2 次分类告警，8 次编辑及 5 次重绘无新增告警。 去重状态不按每次文档 revision 无限累积。

T23：资源与销毁 ​

  • 100 段正文，6 批 × 30 次编辑，逐批强制 GC。
  • 首轮性能压力样本 JS heap 从 99,437,400 到 99,604,392 字节，约增长 0.16 MiB； DOM 固定 419 节点、95 个监听器，没有随编辑次数线性增加。
  • 段落缓存达到并保持 256 项；字体实例 2、覆盖缓存 93、轮廓 52 项/204,426 字节， 宿主布局索引 103；通用旧布局缓存为空。
  • 单实例销毁后段落、布局、字体 face/实例、覆盖、轮廓与告警集合全部为零； 页面 Canvas、诊断 DOM 和该实例注册的 document.fonts 均移除。
  • 独立生命周期轮运行 8 次创建/销毁；强制 GC 后 heap 约 11–13 MB 波动， 最终 DOM 为 18 节点、18 个监听器，与稳定轮相同。部分轮仍可见待释放的 detached DOM， 随后任务/GC 后恢复，没有逐实例增长。
  • 单测另覆盖轮廓 LRU 淘汰、资源缓存 LRU、字体下载订阅释放、失败、超时与缓存失效。

这是有限压力与销毁检查，不能证明所有未来文档没有内存问题。 256 项布局缓存按条目限制，不是整个编辑器 heap 的字节上限；大段落会占用更多内存。 共享 HarfBuzz WASM/模块保留属于运行时复用，不要求销毁一个实例就卸载共享模块。

原始证据：当前版性能、 T01 复测、独立资源/生命周期。

T23：ESM 发行验收 ​

  • 实际 npm pack 后解包为独立消费者，校验包名、版本、作者、MIT/NOTICE 和类型入口。
  • exports 根只含 import/types；require 和内部深路径不可作为公共入口；无 UMD/CJS 产物。
  • 使用实际已声明依赖验证严格 TypeScript，未开启 skipLibCheck，未使用仓库路径别名。
  • 原生浏览器 import map 与独立 Vite 消费端均位于非根路径，执行六类文档： 初始化、真实 Worker 字数与异步保存、字体 HTTP、WASM 整形、PNG 打印。
  • 两种消费者追加本地 WOFF2 场景：实际 tarball 解码、覆盖无缺口、Worker 与打印通过， 并阻止 Bunny 请求；不是只确认某个解码文件存在。
  • 公开字体示例验证默认下载、关闭零请求、手动注册/重复注册、失败提示与重试。
  • Worker/WASM 可以内联在发行 chunk；不错误要求每种资源都有独立 .wasm 文件。
  • 链接锁文件内已安装依赖进行离线消费检查，不等同于公网全新 npm install。
  • 发布预处理只在解包副本上执行，不改工作区包配置；npm publish 不属于本轮动作。

破坏性变更与迁移交付 ​

  1. 原 npm 包替换为 @herberthe/canvas-editor，独立版本线从 0.1.0 开始。
  2. 只支持根 ESM 与 package.json 子路径；不支持 UMD、require、内部深路径。
  3. 移除文字引擎模式与枚举；旧配置报迁移错误。页面固定 Canvas；SVG renderer 请求明确拒绝。
  4. 初始化改用 await Editor.create() 或 await editor.ready；ready 不等待后台基本字体下载。
  5. 字体必须以实际字节/URL 注册；默认下载可关闭，缺字保留占位并提示，不用系统浏览器字体偷偷回退。
  6. 原生字体度量、段落间距、分页、簇编辑可能与旧浏览器度量不同，迁移需重新验收文档与插件。
  7. 性能存在上表所示成本，不承诺旧版速度；复杂结构与单超长段不能作为增量收益宣传。
