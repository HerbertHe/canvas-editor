Canvas Editor 性能优化实施计划 ​

更新日期 2026-11-09。N02–N05 已有实现，历史基准继续作为对照。 必要性判断依据仓库现有实现、提交历史和已归档的基准数据。 历史数值保留各自测量口径。开工时用当前源码重跑对应场景，冻结同版本对照组。 Benchmark · 现有 IME 任务与发布门禁

执行顺序为 N03 和 N04 基线与归因 → 各自最小修复 → 完整复测。 N02 可以独立推进。先补 Firefox 千段的阶段诊断，按调度等待、布局、 绘制和光标锚点拆分后，再决定是否触发 N01。短段和小表格先复测直接同步与按帧消费， 避免把调度开销当作绘制开销。已有脏页、延后绘制、末行窗口、行块位置复用及缓存接纳保护 作为新对照的起点。 实验配置 · 三浏览器验收

继续规则　测量前固定目标场景和主指标。若即使完全去掉某个阶段也难以覆盖预算差额， 将它降为次要任务。观察同一慢样本的阶段分解，阶段 P95 与端到端 P95 不能直接相减。 缺少真实系统 IME 验收的发布决定保持 hold。

基线与验收 ​

  • 同一源码、同一浏览器与渲染后端做 A/B。固定文档、编辑位置、字体哈希、 视口、缩放、DPR、历史设置和预热，记录实际生效的 profile 与实验项。 每档至少三轮，交替运行顺序，保留慢样本。阶段插桩和端到端计时分开跑。
  • 输入任务沿用 handler P95 ≤ 8 ms、geometry P95 ≤ 32 ms 的发布预算。 分别记录 P50/P95/P99/max、消费与合并次数、最终提交和下一次 rAF。 rAF 是刷新代理。确认输入法候选窗和实际交互体验时使用真实系统输入法。
  • 绘制任务记录每次操作的绘制页数、行数、实际重绘面积、主线程 Canvas 调用耗时、 输入到下一次 rAF 和长任务。Canvas 方法返回时间与浏览器光栅化分别记录， 后者用浏览器性能 trace 辅助归因。DPR 1 和 2 分档报告。
  • 正确性以相同输入和几何下的完整重绘为参考。比较同一浏览器、同一 DPR 下的画布像素、 光标、选区和分页。另覆盖合成结束、取消、撤销重做、字体加载、缩放和销毁。
  • 进入启用评估需通过正确性验证，且目标场景的端到端指标改善超出重复运行的波动， 常见短文档和回退场景也要纳入对照。分别记录性能结果和发布决定。 在多浏览器和真实 IME 验收前，新的绘制路径保持显式实验开关。

PERF-N01 单行 IME 局部重绘 ​

当前局部预览替换一行后仍整页重绘。重新汇总 2026-10-30 的原始记录， sync + imePreview 的短段、100 段、1000 段均为每轮 7 次整页绘制， 九轮的每轮平均 _drawPage 调用耗时约 0.17–0.41 ms。 该数据来自旧源码、Chrome、DPR 1，且只覆盖同步 Canvas 调用耗时。 先测当前 Firefox 千段与高 DPR 密集页的逐次绘制和光栅化 trace，再决定是否实现。 历史插桩数据 · 预览绘制入口 · 整页绘制顺序

  1. 在现有 fixture 固定启用 sync 和 imePreview，以全页绘制为 A 组， 仅切换局部绘制作为 B 组。覆盖短段、百段、千段和长段末行。
  2. 通过必要性门槛后，先在现有可见画布实现局部重绘。仅接受页号、行高和整页绘制状态稳定 的简单正文。首次预览若改变全页的搜索或控件高亮可见性，先整页重绘。用旧行和新行的 实际绘制边界并集确定脏矩形，包含字形外扩、下划线和抗锯齿边缘，并按 DPR 向外取整。
  3. 在矩形内恢复背景，按现有绘制顺序重画相交内容。同步限制参与绘制的行， 单独比较只加 clip 与裁剪行遍历的成本。浮动、复杂装饰、跨页或无法计算边界时走整页路径。
  4. 在连续更新、清空和取消时验证旧字形能被完全清掉。合成结束、全页失效或尺寸变化后， 以最新版本完整绘制，避免临时像素残留。

完成条件　局部路径与整页参考逐像素一致，下一帧延迟和绘制工作量下降。 若仅减少 Canvas 调用耗时而端到端变化落在波动内，保留实验结果，暂缓扩大范围。

PERF-N02 批量插入 ​

已实现　大于 32 项且起始索引为非负整数时，performElementInsert 每批最多插入 1024 项。每批只搬移一次后缀，沿用原数组、元素顺序和单次历史记录。 原有逐项路径处理小插入和负索引。上游 #1021 已优化传参方式，内部当时仍逐项插入。 上游 #1021 提交 · 历史插入入口

Chrome 短跑使用原生交互 fixture 的 plain&advanced&tracked 配置。 视口为 1366×720，页面为 800×1100，缩放为 1，关闭 GPU。 正文为 300 段、30,301 元素，每段由 abcdef 重复 14 次后接 xy 和换行组成。 大粘贴为 pasted text\n 重复 1250 次， 小粘贴为 word。调用纯文本粘贴所用的 CanvasEvent.input， 每个场景各跑三次，每次撤销恢复文档。下表为中位数，单位 ms。

PERF-N03 长段编辑向后重排 ​

已实现　同步预览先尝试原有窗口，失败后最多向后检查八行。 仅在总窗口不超过十行、2048 个元素，且变化行仍位于编辑页的原行槽时采用。 窗口外有内容时必须匹配末尾行的来源范围、字形和 caret。 若超限或未收敛，仍由完整布局处理。

报告中长段开头的 IME 几何 P95 为 79.7–133 ms。IME-11 的末行窗口已将 两类末行场景的 P95 降到 2.1 和 6.4 ms，段中仍出现 45/105 次回退， P95 为 76.2 ms。段首的具体失败原因需要单独采集。 IME-11 对照 · 长段基准 · 窗口校验 · 回退路径

  1. 长段专项补齐段首，并保留段中选区替换、段尾与复杂脚本差分。 Chrome 复现中，段首 n、ni、nih 在编辑页内收敛， niha 的断点偏移贯穿窗口，触发完整布局。段中 nihao 可局部替换两行。 同次短跑各采 14 次更新，段中 14 次、段首 6 次使用局部预览。 开启预览时同步阶段 P95 分别为 7.0 ms 和 93.5 ms。 短跑只用于确认工作范围，段首尾延迟仍需单独优化和复测。
  2. 若失败主要来自预览资格检查，先核对索引和约束来源，保留现有安全边界。 若主要来自邻行断点变化，在符合现有脚本和样式限制的正文中试验有界向后重排。 从安全整形边界开始，在来源索引、行高、基线、caret、字形及分页约束收敛后复用后缀。 越过工作量上限或依赖变化时保守回退。单独统计一次失败后后续更新的成本， 避免会话已物化预编辑后直接拿旧模型重试局部预览。
  3. 分别验证中间态与正式选字提交。对每个拼音更新用当前完整布局做断行、像素与 caret 差分， 覆盖混排、长单词、组合字符、字体版本变化、分页和取消。

完成条件　段首和段中实际重排行数及几何尾延迟下降，段尾路径无可复现回归。 仍超既有预算的场景记为未达标。

PERF-N04 大表格按单元格失效 ​

已实现　在保留 16 MiB 估算字节预算与热条目接纳保护的前提下， 条目上限从 512 提到 1024。纯标量单元格命中时直接检查元素身份、布局依赖及字段， 省去克隆和序列化。依赖变化或字段失配时单格重算，含复杂元数据的单元格沿用完整签名。 现有 600 格浏览器差分中，每次更新检查 600 格、标量命中 599 格、签名和重算各 1 格。 位置提交、宿主写回与整表网格检查继续沿用当前实现。

600 格场景的现有缓存仍检查 600 格、计算 88 格，Firefox 几何 P95 为 90 ms。 命中前也有内容克隆和序列化，网格复用后宿主仍会遍历写回。 容量压力数据 · 缓存入口 · 宿主写回

  • 容量隔离实验使用相同旧源码和字节预算，交替比较 512 与 1024 条， 三轮各测 21 次 600 格更新。子布局从 88 格降到 1 格，Chrome geometry P95 三轮范围由 30.6–39.4 ms 降到 27.6–39.2 ms。容量收益在工作量上稳定， 第三轮尾延迟接近，发布预算仍需重跑。
  • 若再优化，先量化剩余的投影、宿主写回和位置提交。仅在稳定网格上缩小写回， 保留高度变化和跨页传播。专项计时可用 TABLE_CACHE_ENTRIES=512 在当前源码上单独复现旧容量的压力。

完成条件　600 格表稳定高度编辑的主要成本与端到端延迟可重复下降。 分别报告检查、子布局和写回计数，以实际改动范围解释各指标。 对照普通表格、合并格增长收缩及跨页重复表头的布局、命中、选区和导出像素。

PERF-N05 千段文档位置提交 ​

已实现　重新分页后，如果规范文字行、横坐标、比例、栏号、可用宽度和页面方向 仍匹配，位置块保留原始行内坐标，读取时使用新的页号、纵坐标和索引。 行内查询以同一份横向几何为基础，在返回 caret 时恢复实际页号和纵坐标。 原生命中直接返回，空白处的回退才筛选完整位置表。

历史专项中，切换 incrementalCommit 后，换行的位置阶段 P95 从 15.8 升到 27.5 ms， 跨页从 16.5 升到 36.3 ms。同一次实验中，换行和跨页的总同步提交 P95 分别从 225.0 降到 42.2 ms、从 272.5 降到 144.4 ms。 本次以已启用增量提交的旧实现为对照。 阶段数据 · 位置复用入口

Chrome 156.0.8078.80、Node 24.22.1、DPR 1，前后各三轮，每轮八次。 拆分计时显示，旧实现换行和跨页的逐行提交 P95 为 27.8 和 30.6 ms， 行目录及页缓存开销低于 1 ms，查询索引为 7.6 和 8.4 ms。 新实现中，后两种场景每次各复用 499 个移位位置块。

PERF-N06 拖选命中与选区绘制 ​

  • 先统计一次事件中各调用者的命中次数，以及选区未变时的绘制次数。 拖选已有 isCompute: false 路径，基准保留它，并区分普通悬停、 开启提示或留痕、正文拖选与表格拖选。
  • 一次 mousemove 在相同页号、坐标和位置上下文下共享命中结果， 由控件光标、提示、留痕和拖选读取。选区和上下文无变化时只省略此次绘制请求， 保留其他调用者的事件和状态处理。
  • 若正文重绘仍是主要成本，先试按旧选区与新选区覆盖的页缩小失效范围。 选区分层另立实验。现有选区在行绘制中合成，直接移到最上层可能改变 浮图、水印和其他装饰的遮盖顺序。

完成条件　固定路径回放中，每帧命中和正文重绘次数下降， 鼠标抬起时最终选区与旧路径一致。分层前后用完整重绘做视觉对照。 鼠标事件入口

PERF-N07 重复水印图块缓存 ​

图片已经缓存。重复图片水印每次绘制仍会创建临时画布并重绘旋转图块。 有实际目标文档时先测图块构建次数和耗时。达到继续条件后缓存紧贴图案的离屏图块， 键包含图源版本、尺寸、间距、缩放和 DPR。 透明度仍在目标 context 合成。保留容量上限，在依赖变更和销毁时释放图块。 可以用 OffscreenCanvas，并用普通临时 Canvas 复用相同缓存策略作为兼容路径。 现有平铺实现 · 离屏预渲染

完成条件　多页重复水印的图块构建次数随配置变化增长，稳定配置下复用。 验证换图、缩放、DPR、打印、水印层级及像素一致性，并记录缓存占用。

PERF-N08 分页画布内存 ​

分页会为每页设置全尺寸画布，具体缓冲何时分配由浏览器决定。先测 100 页和 300 页 在 DPR 1/2 的打开、往返滚动、缩放与销毁，区分从未绘制与已绘制的远端页。 记录全分辨率画布数量、像素总面积和可获得的浏览器进程内存，分开报告 JS heap。 历史脏页回归继续作为正确性入口，覆盖进入视口时刷新、持久观察器、移除页和销毁。 画布创建 · 懒渲染

若全分辨率画布长期驻留是主要成本，保留页的 DOM 尺寸和页号映射， 只为视口与预取窗口分配全尺寸绘图缓冲。离开窗口后有界回收，重新进入时按最新版本重绘。 打印、导出和同步画布读取要验证可按需生成完整页面。

完成条件　活跃像素面积和进程内存峰值下降。快速往返滚动没有稳定可复现的空白页、 可见页绘制延迟回归或光标错位。

PERF-N09 Worker 离屏绘制 ​

IME-13 的排版 Worker 对照中，短行和宽行的几何 P95 分别从 1.5 升到 4.1 ms、 从 9.1 升到 13.9 ms。绘制迁移需要独立验证，并将数据准备、排队和刷新延迟 一同计入。仅在已缩小重绘范围、绘制调用仍明显阻塞主线程时开展单页实验。 现有页面创建时立即获取 2D context， 转移控制权需要在此之前决定后端。首期限定单个可见的简单正文页， 输入、光标定位和交互仍由主线程使用权威几何。 页面创建 · IME-13 Worker 对照 · Canvas 转移规则

  1. 从已提交几何生成紧凑绘制数据，附带页号、尺寸、DPR、文档及几何版本。 记录数据准备、传输字节、排队、绘制和刷新代理。把相同绘制范围作为主线程对照。
  2. 每页仅保留最新待画版本，丢弃过期更新。单独验证滚动、缩放、字体变化、 Worker 崩溃与销毁。使用直接转移时，回退需要创建新的主线程画布并恢复观察和页号映射。
  3. 覆盖高 DPI、像素一致性及同步导出和读回。记录页面额外缓冲和资源生命周期。

继续条件　主线程占用下降，端到端尾延迟无可复现退化，内存和回退成本可接受。 若传输或排队抵消绘制收益，记录实验数据，继续使用局部主线程绘制。
