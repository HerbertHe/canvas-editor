Benchmark：输入与持续删除性能 ​

更新日期：2026-10-23。包含 PERF-01 初始基线、PERF-21（本次修复前）及位置/查询增量提交、持续删除与 Worker 恢复修复后的结果。 默认 baseline 不变，以下优化来自显式实验配置。实现与边界见实验配置与回退。

测量口径 ​

同机 Apple M1 Pro / 8 logical CPUs / 16 GiB，Darwin 25.4.0，Node 24.19.0。字体为 NotoNaskhArabic-Regular.ttf，SHA256 67b5a525a661b607971fbd3f96a81b89d3a768e74534fca84f18ac97e6fab72f。

历史 Chrome 为 155.0.8059.85，本次为 155.0.8059.86。因此为同机同负载历史趋势，不是浏览器版本完全相同的严格 A/B，不能将全部时差唯一归因于代码。

标准负载为 middle / paging / history on / 段落缓存 off / DPR 1 / warmup 1 / 2Hz × 10s，每配置 20 次操作。初始基线一轮，修复前后各三轮；固定 trial 0 比较，不挑最快轮，三轮范围另列。输入取 input handler，删除取 keydown handler。单位为 ms，降低比例为 (修复前 - 本次) / 修复前，负数表示耗时增加。

geometry 为事件到几何提交的代理值，offer→geometry 含驱动排队，均不等于屏幕呈现延迟。阶段 inclusive 时间存在嵌套，不可相加。

验证与发布状态 ​

完整 Vitest 169 文件 / 1072 项通过；最终几何基准、销毁和排空边界修正后，4 文件 / 50 项回归再次通过。TypeScript、ESLint 和最终库构建通过。最终 Chrome 六组四模式差分、348 次结构比较及逐通道导出像素比较通过，含混排、RTL、表格、Unicode、历史、crash 与编辑队列预算不足后的恢复，无 pageerror。

固定预算仍为 handler P95 ≤8ms、geometry P95 ≤32ms，部分文档和压力负载仍超过预算，发布状态保持 hold。默认 baseline 不变，sync opt-in、Worker 实验、transfer 暂缓。超长段落整段排版和全局元数据仍有成本。千段 30Hz 输入中 flow 窗口累计仍为约 8.2–8.5 秒，两轮 geometry P95 仍约 1.3 秒；不能把位置阶段的改善当作高频输入全链路已达标。真实系统 IME/长按、屏幕呈现和长期原生/WASM/GPU 内存待验收；历史其他浏览器结果不替代本次复验。

六轮实际 create/edit/destroy 复验通过：销毁后 Worker、canvas、observer、待处理请求与路径缓存清空。强制 GC 页面 JS heap 为 14223020–14232228 bytes（约 13.56–13.57MiB），只支持短期 JS 生命周期结论，不证明长期原生/WASM/GPU 内存稳定。
