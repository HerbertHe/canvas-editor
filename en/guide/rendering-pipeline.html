Rendering pipeline and timing ​

All text uses HarfBuzz shaping and Canvas glyph-outline painting. “Native layout” below means this project's TextLine/cluster/caret model, not DOM text layout or native OS widgets. Source responsibilities are listed in Architecture.

1. Initialization and the ready boundary ​

Editor.create() is recommended. Mutation and geometry commands during initialization are rejected rather than queued. A small read-only allowlist and explicit asynchronous height measurement have special rules; see migration. With the synchronous constructor, await editor.ready yourself.

Runtime, explicit-font initialization or first-layout errors reject ready; initializationError retains the cause and create cleans up the failed instance. Missing glyphs do not fail initialization. Ready does not wait for background fonts, every image, or every offscreen page: paginated painting can be lazy.

2. Document-to-page flow ​

This is a conceptual expansion of internal calls. Table cells recursively enter paragraph/object layout; text is not laid out independently of all tables first. Internal isCompute: false repaints existing geometry and is not a shortcut after content, width or font changes. Applications should use public commands instead of calling internal render methods.

3. Paragraph shaping and line breaking ​

ElementBridge combines normalized runtime elements into paragraphs and styled spans while preserving logical sources. Bidirectional analysis determines levels; script and style segmentation forms runs, and FontManager selects actual faces by coverage. A CSS family name alone does not provide HarfBuzz with font bytes.

HarfBuzz returns glyph IDs, clusters, advances and offsets. A glyph may represent multiple characters and one character may contribute to several glyphs. The engine shapes a paragraph to estimate breaks, then reshapes at actual line boundaries and refines the breaks until stable. This matters when Arabic joining or ligatures change at a boundary. Visual ordering, alignment and justification follow.

TextLayoutService combines real font metrics and ink bounds to produce ascent, descent, baseline, line content height, clusters and carets, including control minimum widths and inline object boxes. Paragraph spacing before/after remains separate from glyph baselines and content line height, then enters document flow. Uniformly increasing text height cannot model empty paragraphs or page-boundary spacing correctly.

4. Painting a Canvas page ​

GlyphRenderer obtains and caches outline commands from the real font face, then fills Canvas paths. Body text, page chrome, page numbers, list markers, placeholders and auxiliary labels do not fall back to browser fillText, strokeText or measureText. Missing glyphs remain explicit placeholders with diagnostics.

Native coordinates use CSS pixels before host scale and device pixel ratio. Conceptually:

text
x = line.rect.x + glyph.x + glyph.offsetX
y = line.rect.y + line.baseline + glyph.y + glyph.offsetY

Outline paths already use downward-positive Y. The host applies zoom/DPR once; font, layout and painter code must not each apply the same scale. Colors and decorations come from source/cluster styles. Objects retain dedicated painters.

Each layer is conditional. Print mode omits some editing decorations. DOM toolbars, input proxies and overlays have their own stacking context outside this page-paint sequence.

5. Editing sequence ​

The initial renderChange is deferred until ready; normal layout-compute events occur before subsequent nextTick tool updates. The event is not proof that all asynchronous resources and offscreen pages are complete. Hit testing, selection rectangles, visual navigation and logical deletion consume the same native line/cluster/caret geometry as painting.

6. Missing-font recovery ​

Scanning covers body, header/footer, tables and auxiliary text. In-flight requests are deduplicated; memory/IndexedDB cache hits still require actual face registration. Disabling automatic downloads also disables automatic registration from the shared download cache, while explicit URLs and manual registration remain available.

Basic Bunny fonts do not guarantee all Unicode, regional forms, emoji or styles. Network failure never switches to legacy text layout. Preload required fonts and disable background downloads when stable first pagination, offline use or deterministic export matters. Candidate and diagnostic details are in font migration.

7. Incremental reuse and invalidation ​

lab.incrementalCompute: true reuses unchanged native paragraphs. Dirty paragraphs are still fully shaped because contextual shaping and BiDi can affect the entire paragraph. Cached relative indexes are remapped to current sources. Document scanning, container flow, pagination, table fragments and positions still run; complex constraints invalidate conservatively.

CacheCurrent limitRelevant keys
Paragraph layouts256 entriesContent, styles, source identity, font revision, width and line constraints
Glyph outlines1024 entries / 4 MiBFace, glyph and size

Font instances256 entriesInstance keys and font lifecycle

These are internal limits, not stable APIs. There is no promise of convergence within 1–3 lines. T23 stress runs measured full/incremental at about 348/383 ms for many paragraphs and 447/803 ms for one long paragraph. Those tests force all pages to paint and do not measure normal visible-page production typing latency. See acceptance details.

8. Image export and printing ​

command.getImage() prepares temporary drawing state/pixel ratio, paints target pages, waits for the image observer, returns PNG data URLs, then restores state. Printing creates a temporary editor, awaits ready and uses page images plus an iframe to invoke browser printing.

This is neither standalone SVG export nor native vector PDF. HTML/iframe blocks, external images, background font downloads and browser print settings have additional constraints. Ready is not a frozen-resource export barrier; preload fonts, manage image availability and validate real business documents.
